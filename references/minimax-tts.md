# 音频：单词走有道，例句走 MiniMax

**单词发音默认来自有道词典录音**（`scripts/youdao-tts.mjs`，`--word-tts youdao|youdao-us|minimax`）。
它是免费的人类词典读音，且读的就是词条本身；但它是**词典接口而不是 TTS**：只有词典收录的词条有音频，
实测单词与短语词条（`spite`、`comply with`、`in spite of`）返回 MP3，**任何句子都返回 500
`returned null audio`**（13 字符的 `She trembled.` 也一样）。所以例句合成必须继续用 MiniMax，本文其余
部分讲的都是 MiniMax 这一侧。

非官方端点：没有 SLA，可能限流或改接口。取不到词音时脚本**直接抛错停下**，不会静默改用付费合成。
provider 与口音都写进内容寻址的文件名（`youdao-uk-…` / `youdao-us-…` / `minimax-…`），所以换来源会重录，
不会误当成"已存在"而复用旧音频。抓来的音频自用可以，**不要公开分发**。

**入库前一律过一遍响度归一**（`normalizeLoudness`，EBU R128 单遍 loudnorm，目标 −16 LUFS / −1.5 dBTP）。
原因：词典录音本身参差不齐，而且比 MiniMax 例句轻一截——实测有道 30 个词是 −18.4 ~ −23.6 LUFS
（均值 −21.6，真峰值 ≈ −7.8 dBTP），MiniMax 例句是 −15.8 ~ −17.7（均值 −16.9，真峰值 ≈ −1.2 dBTP），
差约 4.7 dB，同一台手机上点单词和点例句就会觉得单词明显小声。归一后实测 −16.4 ~ −16.8，跟例句齐平。
处理版本记在 `YOUDAO_MODEL`（`youdao-dictvoice-l16`）里，也就是写进了文件名指纹：换这一版会让旧的
**原样**音频被判为过期并重录，不会悄悄留着小声的那份。本机没有 ffmpeg 时不报错，原样入库并在
`warnings` 里说明这批词音没归一。走临时文件而不是 `pipe:0`/`pipe:1`：后者在本机上会卡死。

# MiniMax TTS

Use only for an authorized import that needs stored Anki audio. This is an import-time operation,
never a request from card-template JavaScript.

## Configuration

The scripts check `MINIMAX_API_KEY`, then the macOS Keychain item named `anki-minimax-tts`, then
`.env` in the skill root. To use a different dotenv file, pass `--minimax-env-file /absolute/path/.env`.
To store the key in the Keychain:

```sh
read -s "MINIMAX_KEY?MiniMax API key: "
security add-generic-password -U -a "$USER" -s "anki-minimax-tts" -w "$MINIMAX_KEY"
unset MINIMAX_KEY
```

Copy `.env.example` to `.env`, fill in `MINIMAX_API_KEY`, and keep `.env` out of Git. An environment
variable is fine for automation, but never commit either form of the key and never put it in note JSON.
The China endpoint is `https://api.minimax.cn/v1/t2a_v2` and uses Bearer authorization; switch it with
`--minimax-endpoint` if the account is provisioned elsewhere.

## Commands

```sh
node "$SKILL_DIR/scripts/import-vocabulary.mjs" /absolute/path/to/notes.json --dry-run \
  --minimax-voice "English_Steady_Female_1"

node "$SKILL_DIR/scripts/import-vocabulary.mjs" /absolute/path/to/notes.json \
  --confirmed --minimax-model "speech-2.8-hd" --minimax-speed 1

node "$SKILL_DIR/scripts/add-audio-to-existing.mjs" \
  --deck "all in one::微语境闪卡" --word "exempt" --minimax-voice "English_Steady_Female_1" --dry-run
```

TTS is on by default. The default model is `speech-2.8-hd`, speed `1`, and a conservative 11-second
interval is kept between fresh synthesis requests to avoid RPM errors; override it with
`--minimax-min-interval-ms NUMBER` only when the MiniMax quota supports a higher rate. Voice, model,
speed, key variable, Keychain service, endpoint, and media prefix can all be overridden with the flags
listed by the script's usage line. `--without-tts` is only for an explicitly requested silent import.

## What gets created

One file for `Word` and one for each populated `Sentence{i}` — four to six per note:

```
<prefix>-<word-slug>-word-<fingerprint>.mp3
<prefix>-<word-slug>-sentence-1-<fingerprint>.mp3
```

`fingerprint` is `sha256(JSON.stringify({text, model, voiceId, speed}))[:16]`, so the name is stable
while any of those change invalidates it. Before each synthesis the script asks Anki whether the file
already exists (`retrieveMediaFile`); cached files are reused and never charged twice, which makes a
stopped import safely re-runnable. New audio arrives as hex-encoded MP3 from the synchronous T2A
endpoint, is decoded locally, and is uploaded with AnkiConnect `storeMediaFile`.

The word file is written to `WordAudio` and each sentence file to `AudioSentence{i}` as a **raw
filename**. The templates set `audio.src` from those fields and drive playback themselves: the back
plays word → sentence in sequence, the front exposes only a manual button so the target word is never
spoken before the answer. That is why this note type has no `AudioWordAuto` (`[sound:...]`) field and
why the importer must not write one — Anki's native answer-side autoplay would play the word twice.

`--media-prefix` changes the leading token (default `minimax`). It does not change the fingerprint, so
audio generated by an older script variant — different prefix, different fingerprint input — will be
generated again rather than reused; that is expected, not a bug.

## Gates

Run `node "$SKILL_DIR/scripts/ensure-audio-fields.mjs"` before the first import. It is read-only, and
exits with a repair command when `WordAudio` or `AudioSentence1..5` are missing; run that command with
`--apply` only after the user authorizes changing the note type.

The real import also requires `--confirmed`, and that check runs **before** any paid TTS request.
Use `--dry-run` first: it validates everything, prints the planned filenames, and reports how many
files would be newly generated versus reused, so the cost can be stated honestly before confirmation.
